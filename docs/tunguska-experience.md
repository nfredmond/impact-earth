# Tunguska experience

## Design

The experience is a five-chapter field guide: location, atmospheric entry, observation point, composition experiment, and saved field note. Navigation advances on request. The globe occupies the main stage; a reading column supplies context and controls. On phones, the stage sits above the reading column.

Use the existing Chakra Petch display face and system body text. Use space blue `#060a12`, slate `#132432`, paper white `#e8ecf4`, atmospheric blue `#93cddd`, amber `#ffba79`, and forest green `#4f7565`. Reserve amber for the incoming object and blue for observer geometry. The atmospheric cross section is the main new visual, with a shared height axis for comparisons. Decorative cards and automated chapter changes add no information and are omitted.

Historical observations carry a NASA source link. Preset parameters and simulated outcomes are labeled separately. The atmosphere drawing is a schematic, not a reconstruction of the observed flight path. Ground-level sightlines and arrival times are outside this release.

The experiment changes composition while holding the preset's diameter, entry speed, angle, target, date, and location fixed. Observer distance changes along a due-south great-circle route. Saved notes retain inputs and numerical summaries; reopening an experiment recalculates it with the installed model. Local storage errors must remain visible.

## Sources

- NASA, [115 Years Ago: The Tunguska Asteroid Impact Event](https://www.nasa.gov/history/115-years-ago-the-tunguska-asteroid-impact-event/), June 30, 2023.
- NASA, [Tunguska Revisited](https://www.nasa.gov/solar-system/tunguska-revisited-111-year-old-mystery-impact-inspires-new-more-optimistic-asteroid-predictions/), June 26, 2019.

The app's existing impact equations supply modeled values. This release does not validate those equations against additional physical observations.

## Verification

- All 45 tests pass, including 12 new story and notebook cases. The tests cover fixed experiment inputs, observer geometry, local persistence, storage failure, capacity, invalid data, escaped exports, saved values, and scenario restoration.
- An isolated mutation run first accepted a comment-only change. Ten deliberate changes then failed the intended assertions: ignoring composition; using the wrong distance divisor; placing the observer north; bypassing stored notes; removing the wrong note; suppressing storage errors; bypassing the capacity limit; leaving titles unescaped; replacing saved energy; and skipping scenario restoration.
- Browser checks cover story entry, chapters, three observer distances, material changes, pause/resume, returning to the previous scenario, saving, reloading, reopening, and the notebook's Escape/focus return. Desktop and 390 px phone layouts were inspected. The HTML generated by the actual download action was captured and rendered in the browser. Saving the browser download to the user's filesystem was not confirmed.
- The production build and lint checks succeed without warnings. The largest JavaScript chunk is about 364 KB, compared with the previous 991 KB main bundle. Report generation loads on demand. The 3D renderer skips frames when hidden or covered by a story diagram.
- The Linux Debian package installs and passes the native story journey with sandboxing enabled. The check loads the population grid, changes the material to iron, confirms a surface-impact result, saves a note, and finds it in the notebook. The packaged observer view was inspected visually. The launch wrapper clears inherited `ELECTRON_RUN_AS_NODE`; no `--no-sandbox` flag is used for the installed app.
- The release workflow builds installers on native Linux, Windows, and macOS runners, runs the desktop journey, and publishes only after all three succeed. Windows and macOS checks exercise packaged executables, not the interactive installer or Gatekeeper/SmartScreen prompts. Run-specific results are recorded in GitHub Actions.
- The desktop journey accepts a comment-only mutation and rejects three deliberate faults in isolated app copies: a missing population file, an iron selection that does nothing, and an empty notebook list. The material probe initially survived because iron was already selected. The corrected journey first selects stone and requires an airburst, then selects iron and requires a surface impact. These checks exercise packaged UI behavior; screenshots still require visual review, and installer prompts remain outside the journey.

Tests cover application behavior, not the scientific validity of the physical model. The UI checks do not establish performance on a physical phone.

## Local preview

The preview runs from this checkout at `http://localhost:5173`, in the transient user service `impact-earth-dev.service`. Check with `systemctl --user status impact-earth-dev`; stop with `systemctl --user stop impact-earth-dev`. This keeps the preview process separate from the T3 desktop process group. The service is not enabled for login.
