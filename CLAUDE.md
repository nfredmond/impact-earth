# Impact Earth — dev notes

Vite + React 19 + TypeScript + Three.js + Zustand static SPA. No backend.

- `npm run dev` (Vite), `npm test` (vitest — physics validated against published event
  values; keep those tolerances honest), `npm run build` (tsc -b + vite build).
- `tsconfig` has `erasableSyntaxOnly`: no constructor parameter properties or enums.
- State flows one way: `src/state/store.ts` (Zustand) → recomputes `SimulationResult`
  (pure functions in `src/physics/`) and `HumanImpact` (`src/casualties/casualties.ts`,
  needs the popgrid loaded) on every scenario change. The 3D scene (`src/scene/GlobeView.tsx`)
  subscribes to the store; a bumped `animationNonce` replays the cinematic.
- Lat/lng ↔ 3D mapping lives in `src/scene/geo.ts` (`latLngToVec3` matches equirect
  textures on `THREE.SphereGeometry`; `vec3ToLatLng` is its inverse — round-trip tested
  in-browser via the placement raycast).
- `public/data/popgrid.bin` is generated by `node scripts/build-popgrid.mjs`
  (downloads SimpleMaps world cities CSV; needs a browser User-Agent — plain curl gets 403).
  Format: 720×360 Float32 LE, row 0 = +89.75° lat, col 0 = −179.75° lng, population count per cell.
- Historical events: `src/data/events.ts`. Event params are tuned so the physics engine
  reproduces published crater sizes/yields — if you touch the physics, re-run the tests.
- Damage rings are capped at 6,000 km (`MAX_RING_KM` in `src/physics/impact.ts`) because
  point-source blast scaling is meaningless at planetary scale; casualty integration
  depends on that cap staying sane.
